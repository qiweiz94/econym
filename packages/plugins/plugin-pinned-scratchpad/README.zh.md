# @econym/dsh-plugin-pinned-scratchpad

[English](README.md) | 中文

模型可见的 `scratchpad_update` 工具：一个由智能体显式维护的按会话键/值存储，在每次系统提示词组装时渲染为固定的 `<agent_scratchpad>` 块，使固定事实在上下文压缩中存活——提示词按每次请求重新组装、从不被压缩，因此该区段渲染的内容不受压缩从对话记录中丢弃任何内容的影响。

## 功能

在 `ctx.tools` 上注册一个工具，在 `ctx.systemPrompt` 上注册一个区段：

- `scratchpad_update(key, value)` 在调用方智能体的便签本中新增/替换或删除一个条目。字符串 `value` 新增一个键或替换已有键；`null` 删除一个已有键，若该键不存在则大声失败。`key` 与 `value` 都会被去除首尾空白且必须非空；`key` 必须为单行；两者都不得包含字面的 `<agent_scratchpad>` / `</agent_scratchpad>` 框架标记，因此存储的值永远无法提前闭合渲染块并把文本夹带到分隔符之外。该工具要求存在拥有会话的智能体——没有 `agent`（没有会话来拥有该存储）的调用方会被拒绝，而不是静默地无操作。
- `scratchpad:pinned` 提示词区段将调用方智能体的当前条目按插入顺序渲染为 `<agent_scratchpad>`/`</agent_scratchpad>` 之间的 `key: value` 行；空存储或无智能体的组装则不贡献任何内容（`''`）。

## 持久化模型

每次被接受的 `scratchpad_update` 调用都会追加一条 `scratchpad/write` 会话事件，携带**完整的替换条目列表**，而非增量。当前存储通过扫描调用方智能体的会话日志、读取最新一条 `scratchpad/write` 事件的 `entries` 折叠得到——最后写入者获胜，没有单独的实时镜像。这与 `dsh-todo` 的 `todo/write` 事件所用的整存储快照模式相同：恢复与派生（fork）仅靠回放日志即可重建存储，对先前写入过的日志重新挂载也会渲染出相同的区段内容，而无需重新执行任何工具调用。

`scratchpad/write` 是模型可见的（该区段将其渲染进每一次请求），并且从不带有会话日志包络的 `ignorable` 标记，因此不了解该事件类型的读取方必须拒绝该日志，而不是静默丢弃固定状态。

## 字节预算：在写入时强制执行、大声失败

`Config.totalBudget`（默认 1000）约束完整渲染出的 `<agent_scratchpad>` 块的 UTF-8 字节长度，包含包裹标签——而非 token 数，因为本框架没有面向所服务模型的分词器。若某次 `scratchpad_update` 调用会使结果块超出预算，该调用在写入日志之前就会被拒绝：错误信息会列出所需字节数、配置的预算、以及当前已使用的字节数，且不会追加任何 `scratchpad/write` 事件。存储中已有的条目永远不会被静默截断以适配预算——模型必须自行缩短某个值或删除某个条目。`totalBudget` 必须至少等于最小的单条目块的字节长度；更小的值会在插件加载时大声失败。

预算只约束 `set` 路径。在更大的预算下写入、之后预算被调小的日志仍能完整回放并渲染（`./invariant` 中的包级不变量刻意不检查渲染后的大小，因为那是当前每次部署的配置，而非持久化形状规则）；对一个已超出预算的种子存储执行 `delete` 调用仍会被接受，因此即便在预算重新满足之前任何进一步的 `set` 都无法成功，把存储裁剪回预算之内始终是可能的。

## 导出形态

函数/命名空间插件：导出 `name` / `inject` / `apply`，且**没有**默认导出。多余的 `export default` 会被 Loader 的 `unwrapExports` 折叠并丢掉 `inject`（参见 [docs/postmortem/0001](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/postmortem/0001-acp-default-export-drops-inject.md)）。

## 模型体验

### 固定便签本提示词区段

#### 模型看到什么

模型看到 `scratchpad:pinned` 区段，它用一对稳定标签包裹调用方智能体的当前条目，每个条目一行 `key: value`，按插入顺序排列。在首次写入之前以及无智能体的组装中，它不贡献任何内容（没有标签，也没有任何行）。

##### 该字段的原文，需要时

```markdown
<agent_scratchpad>
goal: ship the fix
branch: lane/fix
</agent_scratchpad>
```

#### Token 影响

空存储时为零。非空存储的开销与其渲染后的大小成正比，并被 `Config.totalBudget`（默认 1000）硬性限制——完整的块（包含包裹标签）永远不会超出该预算，因为会导致超出的写入在写入日志之前就已被拒绝。

#### KV Cache 影响

该区段渲染在框架稳定区段之后（`order: 1010`，紧随 `plan:policy` 区段之后），因此一次被接受的 `scratchpad_update` 调用只重写请求的尾部，在存储未变化的多个回合之间保持可缓存前缀逐字节不变。改变存储的一次调用会使下一次包含该区段的请求从该区段边界起的缓存复用失效；下方的工具 schema 不受此影响。

### 工具 Schema

#### 模型看到什么

模型看到生成的 `scratchpad_update` schema：一个必填的 `key` 字符串与一个必填的 `value` 字段（字符串或 `null`）。该工具的描述声明该区段会渲染进每一次请求、在压缩中存活，并受一个字节预算约束，超出预算会大声失败。插件配置（`totalBudget`）在加载时校验，若其值小到无法容纳任何条目则大声失败；它不改动任何 schema 字段，只决定模型在某次 `set` 调用开始失败之前能积累多少字节的块内容。

#### Token 影响

每次工具可见的请求都有固定的 schema 成本，与上方提示词区段当前是否渲染任何内容无关。调用结果（`action`、`key`、完整的 `entries` 数组、以及 `usage`）随当前存储的大小变化，同样受 `totalBudget` 约束。

#### KV Cache 影响

在 schema 定义与工具可见性不变时前缀稳定；调用结果是被追加的对话历史，本身不会触及上方区段所拥有的系统提示词前缀。

## 已知限制与待办

- **按智能体而非按对话**——存储以调用方智能体自身的会话日志为键。从父智能体派生的子智能体或子代理不会继承父智能体的便签本，也无法查看或写入它；每个想要固定工作记忆的智能体都需要在自己的上下文中挂载该插件，并写入自己独立的存储。
- **无跨条目结构**——条目是扁平的 `key: value` 字符串；没有嵌套、列表或带类型的值，除插入顺序外也没有其他排序控制（更新一个已有键保留其原位置；一个新键则追加在末尾）。
- **单一预算、单一计量单位**——`totalBudget` 以字节约束整个渲染块；没有单条目上限，因此一个较大的值可能占用大部分预算，给其他条目留下很少空间。模型必须自行管理（缩短值、删除过期条目）。
- **无历史或撤销**——只有最新快照会被渲染或返回；已删除或被覆盖条目的旧值无法从该工具自身的输出中恢复（它仍保留在持久化会话日志中，作为一条被取代的 `scratchpad/write` 事件，但本包中没有任何代码把它读回来）。
